# Wayback Audit

Инструмент собирает **историю цен товаров** из архива Wayback Machine, извлекает данные с сохранённых снимков страниц с помощью LLM и собирает результат в Excel-отчёт с аналитической справкой.

**Как это работает:** вы загружаете файл со списком URL товаров → инструмент находит все снимки этих страниц в архиве за нужный период → скачивает HTML → LLM строит CSS-рецепт парсинга → локально извлекает цену, наименование, артикул → собирает Excel с динамикой по датам и график изменения цены.

Работает локально на вашем компьютере. Интерфейс открывается в браузере.

| Что | Зачем | Как проверить |

```bash
cd путь/к/Wayback_Audit
```

## Шаг 2. Первый запуск

**Windows:**

```powershell
.\start_web.bat
```

**Linux / macOS:**

```bash
./start_web.bat
```

Первый запуск идёт **3–5 минут** — скрипт по шагам:

1. проверяет Python;
2. создаёт виртуальное окружение `.venv`;
3. ставит зависимости из `requirements.txt`;
4. поднимает интерфейс на **http://127.0.0.1:5000/** и открывает браузер.

Когда в терминале появится строка «Flask: http://127.0.0.1:5000», браузер откроется сам. Если не открылся — перейдите по адресу вручную.

**Остановить** — `Ctrl+C` в окне терминала. Окно должно оставаться открытым всё время работы: это и есть работающий сервер.

**Следующие запуски** — та же команда, но уже за **5–10 секунд**: venv и пакеты не пересоздаются.

### Настройка ключа Foundation Models

Создайте файл `.env` в корне проекта (шаблон — `.env.example`):

```
OPENAI_API_KEY=your_key_here
OPENAI_BASE_URL=https://foundation-models.api.cloud.ru/v1
FLASK_SECRET_KEY=change_me_in_production
```

| Переменная | Что это |
|---|---|
| `OPENAI_API_KEY` | ключ доступа к **Foundation Models** (Облако УВА) |
| `OPENAI_BASE_URL` | адрес API Foundation Models. **Обязательно** с `/v1` на конце |
| `FLASK_SECRET_KEY` | секрет для сессий Flask. **Опционально:** если не задать — используется `dev-change-me`. Для локальной работы можно пропустить |

> **Про названия переменных.** Инструмент общается с моделью по **OpenAI-совместимому протоколу** — это стандарт индустрии, поддерживается Foundation Models. Поэтому переменные называются `OPENAI_API_KEY` и `OPENAI_BASE_URL`, хотя фактически это ключи и адрес **Foundation Models**. Не путайтесь.

Ключ используется для обучения рецептов парсинга (шаг 2.5).

**Как сгенерировать надёжный `FLASK_SECRET_KEY`** (для продакшена):

```powershell
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Скопируйте вывод в `.env`. Для локальной работы можно оставить `change_me_in_production` или вовсе не задавать.

## Шаг 3. Подготовить файл

Подойдёт **.xlsx** или **.csv**. Требование одно: должна быть колонка с URL-адресами страниц товаров.

Инструмент сам найдёт нужную колонку — распознаются названия **url, ссылка, link, адрес, page, страница, href** и подобные. Дополнительно могут быть колонки **наименование** и **текущая цена** — они используются для сопоставления и расчёта расхождений.

Пример:

| url | name | current_price |
|---|---|---|
| https://ip-sol.ru/catalog/detail/ltv-3cnb20-f28-ltv-tsilindricheskaya-ip-videokamera/ | LTV-3CNB20-F28 | 18000 |
| https://www.tinko.ru/catalog/product/233395/ | ИП104 Гранат | 464 |

**Чем точнее URL, тем лучше результат.** Если в URL есть UTM-метки или трекинг-параметры (`?srsltid=...`, `?utm_source=...`) — они автоматически отбрасываются при поиске снимков.

## Шаг 4. Запустить обработку

1. **Создайте новый проект** — кнопка «+ Новый проект».
2. **Загрузите файл** — перетащите его в область или щёлкните по ней.
3. **Укажите имя проекта** и **период** (с какой даты искать снимки).
4. Нажмите **«Создать»**.

Дальше инструмент идёт по шагам сам:

| Шаг | Что делает |
|---|---|
| **0. Разбор входного файла** | читает URL, наименования, цены |
| **1. Сбор снимков из архива** | запрашивает Wayback CDX API: какие снимки есть за период |
| **2. Скачивание HTML** | скачивает сохранённые страницы (с дедупликацией) |
| **2.5. Обучение рецепта** | LLM изучает структуру HTML и строит CSS-рецепт для каждого домена |
| **3. Парсинг данных** | локально извлекает цену, наименование, артикул по рецепту |
| **4. Сборка Excel** | собирает отчёт с ценами по датам |

**Статус** каждой стадии виден в интерфейсе (карточки шагов).

Поиск можно **остановить** («Остановить») и продолжить позже — прогресс сохраняется. Кнопка **«Продолжить»** продолжает с места обрыва, **«Заново»** — сбрасывает и начинает заново.

**Промежуточные результаты** сохраняются на диск автоматически после каждого шага — в папке `data/<имя_проекта>/`. Если процесс прервётся — работа не пропадёт.

## Шаг 5. Забрать результат

Кнопка **«Скачать report.xlsx»** в шапке проекта.

В отчёте — **одна строка = один снимок товара**:

- `url` — ссылка на оригинал
- `date` — дата снимка
- `price_current` — найденная цена
- `price_old` — старая цена (если была)
- `input_price` — цена из входного файла
- `diff_percent` — расхождение в %
- `match_score`, `match_status` — качество сопоставления наименований
- `confidence` — уверенность парсинга

Дополнительно — **аналитическая справка** в интерфейсе:
- сводка по товару: мин/макс цена, изменение за период;
- **график динамики цены** по датам снимков;
- таблица с датами, ценами и ссылками на Wayback.

## Сколько это занимает

Ориентиры:

- **1–3 минуты** на домен при обучении рецепта (обращение к LLM)
- **8 сек** между запросами к Wayback (соблюдение лимитов)
- **длительность зависит от количества URL:** для 400 URL с 5 снимками каждый — **1–3 часа** на всё

Текущий прогресс виден в шапке проекта: сколько доменов обработано, на каком шаге сейчас.

## Если что-то пошло не так

**«command not found: python» / «python не является внутренней командой»**
Python не установлен или не добавлен в PATH. Переустановите с python.org, на Windows отметьте «Add Python to PATH».

**`start_web.bat` открывается и сразу закрывается**
Запустите его **из cmd** (не двойным кликом), чтобы увидеть ошибку:
```cmd
cd путь\к\Wayback_Audit
start_web.bat
```

**Кракозябры в окне `.bat`**
Файл сохранён в UTF-8. Пересохраните в **ANSI** (Блокнот → Сохранить как → Кодировка → ANSI).

**`ModuleNotFoundError: No module named '...'`**
Окружение неполное. Удалите `.venv` и запустите скрипт заново:
```powershell
Remove-Item .venv -Recurse -Force
.\start_web.bat
```

**Браузер не открылся сам**
Откройте http://127.0.0.1:5000/ вручную.

**Wayback отдаёт 503 / 504 / «нет снимков»**
Сервер архива перегружен — частые ошибки в вечернее время. Подождите и нажмите «Продолжить» — инструмент пропустит уже обработанные домены и вернётся к проблемным.

**Цены не находятся на конкретных позициях**
Не все сайты сохраняются в Wayback. Проверьте URL вручную: `web.archive.org/web/2025*/<ваш-url>` — если «Архивная копия не сохранена», инструмент тут не поможет.

**Нужен подробный журнал**
Панель «Логи» в правом верхнем углу, либо файл `data/<проект>/logs/web_run.log`.

## Настройка

Тонкие параметры лежат в папке `config/` — обычные YAML-файлы:

| Файл | За что отвечает |
|---|---|
| `app.yaml` | общие настройки: год начала, пауза между запросами, retry |
| `llm.yaml` | модель, температура, лимиты обращений |
| `clean.yaml` | очистка HTML перед отправкой в LLM (какие теги удалять, лимит размера) |
| `extract.yaml` | параллельность, паузы |

Ключи и адрес API хранятся в файле `.env` в корне проекта — он создаётся вручную из `.env.example` и **в репозиторий не попадает** (см. `.gitignore`).

Формат `.env`:

```
OPENAI_API_KEY=your_key_here
OPENAI_BASE_URL=https://foundation-models.api.cloud.ru/v1
FLASK_SECRET_KEY=change_me_in_production
```

> **Про названия переменных.** `OPENAI_API_KEY` и `OPENAI_BASE_URL` — это стандарт **OpenAI-совместимого протокола**, поддерживаемый Foundation Models. Фактически это ключ и адрес **Foundation Models**.

Не коммитьте `.env` в git — там **ключи**.

Рабочие данные лежат в `data/`:
- `data/<проект>/` — артефакты конкретного проекта;
- `data/_recipes_cache/` — общий кэш рецептов парсинга по домену.

## Работа из командной строки

Полный пайплайн:

```powershell
& ".venv\Scripts\python.exe" run.py `
    -p имя_проекта `
    -i "data\имя_проекта\input\input.csv" `
    -s all `
    --from-date 2025-01-01 `
    --excel report.xlsx
```

Отдельные шаги:

```powershell
# Только разбор входа
& ".venv\Scripts\python.exe" run.py -p имя_проекта -i input.csv -s 0

# Только сбор снимков из CDX
& ".venv\Scripts\python.exe" run.py -p имя_проекта -s 1 --from-date 2025-01-01

# Только скачивание HTML
& ".venv\Scripts\python.exe" run.py -p имя_проекта -s 2

# Только обучение рецептов
& ".venv\Scripts\python.exe" run.py -p имя_проекта -s 2.5

# Только парсинг
& ".venv\Scripts\python.exe" run.py -p имя_проекта -s 3

# Только сборка Excel
& ".venv\Scripts\python.exe" run.py -p имя_проекта -s 4
```

**Флаг `--resume`** — продолжить с места остановки, не пересобирать готовое:

```powershell
& ".venv\Scripts\python.exe" run.py -p имя_проекта -i input.csv -s all --resume
```

**Флаг `--force`** — обучить рецепты заново, игнорируя кэш (осторожно):

```powershell
& ".venv\Scripts\python.exe" run.py -p имя_проекта -s 2.5 --force
```

## Устройство проекта

| Каталог | Содержимое |
|---|---|
| `wayback_audit/core/` | ядро: пути, конфиг, логгер, парсер входных файлов, матчинг наименований |
| `wayback_audit/steps/` | шаги пайплайна: 0 — разбор входа, 1 — CDX, 2 — скачивание, 2.5 — обучение, 3 — парсинг, 4 — Excel |
| `wayback_audit/parsers/` | парсер HTML по рецептам + хранилище рецептов |
| `wayback_audit/web/` | Flask-интерфейс: роуты, шаблоны, статика |
| `config/` | YAML-настройки |
| `data/` | рабочие данные проектов, общий кэш рецептов (создаётся сам) |
| `run.py` | CLI-точка входа |
| `start_web.bat` | запуск веб-интерфейса (Windows) |
| `requirements.txt` | зависимости Python |

Скачивание HTML идёт через `https://web.archive.org/web/<timestamp>id_/<url>` — «сырой» HTML без подмены ресурсов. Поиск снимков — через Wayback CDX API. Модель вызывается по OpenAI-совместимому HTTP API (Foundation Models).
